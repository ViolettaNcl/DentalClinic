DentalClinic — локальный запуск
================================

Основной README на GitHub (English): README.md
Русский README: README.ru.md
Подробная инструкция: docs/DEVELOPER_GUIDE.md

Требования
----------
- .NET SDK 10.x
- SQL Server 2019+ / Azure SQL / SQL Server в Docker
- Git
- Опционально: Node.js 22 и Docker Desktop

Вариант 1: .NET SDK
-------------------
1. В PowerShell из корня репозитория:

   dotnet tool restore
   dotnet restore
   Copy-Item appsettings.Example.json appsettings.json

2. Откройте appsettings.json и замените placeholders:
   - ConnectionStrings:DefaultConnection
   - Jwt:Key (минимум 32 UTF-8 байта)
   - Jwt:Issuer / Jwt:Audience
   - AllowedOrigins
   - Clinic (публичные контакты)
   - Gemini / ElevenLabs при необходимости

   appsettings.json добавлен в .gitignore. Не коммитьте реальные значения.

3. Примените migrations и запустите:

   dotnet ef database update
   dotnet run

4. Адреса из launch profiles:
   http://localhost:5192
   https://localhost:7063
   Swagger в Development: /swagger
   Health check: /health

Вариант 2: Docker Compose
-------------------------
1. Создайте локальный .env:

   Copy-Item .env.example .env

2. Замените ВСЕ placeholders в .env.

3. Запустите:

   docker compose up --build

   App: http://localhost:8080
   SQL Server: localhost:1433

Важно: команда docker compose down -v удаляет named volumes, включая данные БД.

Администратор
-------------
Приложение намеренно не создаёт default admin/password. Первый super-admin
создаётся владельцем deployment через контролируемый процесс. Не добавляйте
публичные тестовые credentials в исходный код или документацию.

Production
----------
Git-triggered Vercel deployment сейчас намеренно выключен:
vercel.json -> git.deploymentEnabled = false.

Push не запускает Git-интеграцию Vercel. Однако push в main запускает CI и
может вызвать GHCR publication, настроенную FTPS-доставку и VCR retention.
Контролируемый release описан в docs/DEPLOYMENT.md.

Безопасность
------------
- Не коммитьте .env, appsettings.json, API keys, DB passwords и JWT key.
- Login создаёт HttpOnly cookie; token не возвращается в JSON.
- Vulnerabilities не публикуйте в Issues: следуйте SECURITY.md.
