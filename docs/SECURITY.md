# Безопасность и эксплуатационные ограничения

[Документация](README.ru.md) · [Сообщить об уязвимости](../SECURITY.md) · [English](en/SECURITY.md)

Документ описывает реализованные меры защиты и риски, которые остаются ответственностью владельца развёртывания. Это не сертификат безопасности, результат пентеста или гарантия отсутствия уязвимостей.

## Данные и границы доверия

Защиты требуют учётные записи и хеши паролей, заявки, отзывы, уведомления, переписка, административные права, база знаний клиники, ключи внешних сервисов и доступ к SQL Server.

Недоверенными считаются входящие запросы, идентификаторы ресурсов, заголовки, загруженные файлы, ответы ИИ, материалы административной базы знаний, внешние скрипты и данные старых версий приложения.

## Секреты

В примерах конфигурации должны находиться только заглушки. Данная проверка документации не является полным сканированием истории Git на утечки.

Для локальной разработки используйте ASP.NET Core Secret Manager; для размещённых сред — настройки секретов Vercel/GitHub или отдельное хранилище секретов. Разделяйте доступ к разработке, тестированию и production.

Не публикуйте ключи, пароли, строки подключения, данные пациентов, резервные копии или неочищенные журналы в исходниках, Issues, PR и снимках экрана. При утечке отзовите и замените секрет: удаление текста из Git не прекращает доступ.

## Аутентификация и сессии

| Механизм | Реализация |
|---|---|
| Пароли | BCrypt; минимум 8 символов, заглавная и строчная буквы, цифра и специальный символ |
| JWT | Проверка подписи HMAC, издателя, аудитории и срока действия; нулевой допуск времени |
| Браузерная сессия | Cookie `dc_auth`: `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS |
| Передача токена | Вход не возвращает токен в JSON; браузер не хранит его в local/session storage |
| Авторизация | Роль и принадлежность ресурса; права супер-администратора дополнительно проверяются в SQL |
| Защита администраторов | Запрет удаления собственной учётной записи и удаления/понижения последнего супер-администратора |
| Отзыв сессий | Проверка `TokenVersion` с локальным кешем на 45 секунд |

Смена пароля или административного доступа увеличивает сохранённую версию токена. Другой экземпляр приложения может видеть старое значение до истечения своего кеша. Выход очищает cookie и обновляет кеш текущего процесса, но не сохраняет увеличение версии в БД: это **не долговечный отзыв токена на всех серверах**.

В Development проверка токена допускает отдельные временные ошибки БД; в production такие запросы отклоняются. SignalR использует ту же cookie и не принимает токен через `access_token` в URL. Ответы аутентифицированного API получают `no-store`.

Учётные записи администраторов и общедоступные пароли по умолчанию не создаются.

## Origin, CSRF и прокси

Для изменяющих состояние запросов с cookie и операций входа middleware проверяет `Origin`/`Referer`, а также отклоняет `Sec-Fetch-Site: cross-site`. Платные ИИ-маршруты требуют допустимый `Origin` в production. Исключения для инструментов без заголовков происхождения предусмотрены в Development/Testing.

CORS не заменяет авторизацию и проверку происхождения запроса.

Обработка перенаправленных заголовков включается при `VERCEL=1` с ограничением в один переход. Списки известных прокси/сетей очищаются в коде: инфраструктура должна исключать прямой доступ с поддельными заголовками. Сам флаг не доказывает доверие к отправителю.

## Ограничение нагрузки и расходов

| Группа запросов | Запросов на клиента в минуту |
|---|---:|
| Создание заявки | 3 |
| Регистрация и вход | 8 |
| Чат и SSE | 15 |
| Озвучивание | 4 |
| Перевод | 40 |

В production сочетаются локальные ограничения ASP.NET Core и распределённые счётчики в SQL. ИИ-запросы дополнительно ограничены размером тела, проверкой происхождения, тайм-аутами и отменой. Ключ Gemini передаётся сервером в заголовке, а не в URL.

Эти меры снижают риск злоупотреблений, но не заменяют сетевую защиту от DDoS.

## Целостность данных

DTO ограничивают формат и размер входных данных; ограничения и индексы БД защищают допустимые значения, уникальность и идемпотентность. Расписание проверяется централизованно; конфликтующие изменения используют сериализуемые транзакции. SQL application locks применяются в административных операциях, проверке email между ролями и начальном заполнении.

Публичные выборки ограничены по объёму. Для экспорта слишком большой диапазон дат даёт `400`, превышение лимита строк — `422`. Временные ошибки БД преобразуются в безопасный `503` без раскрытия внутренних подробностей.

## Загрузка изображений

Аватар владельца: до 3 МБ; фотография врача: до 5 МБ и только для Admin. Проверяются расширение и сигнатура JPG/JPEG, PNG или WebP. Байты и MIME хранятся в SQL. Аватар доступен владельцу; фотографии врачей доступны публично.

Проверка сигнатуры не включает декодирование, антивирусное сканирование, удаление метаданных или защиту от чрезмерных затрат при распаковке. При повышенных требованиях нужен отдельный этап обработки изображений.

## ИИ и конфиденциальность

Факты клиники поступают из конфигурации и SQL. Материалы базы знаний очищаются, ранжируются и ограничиваются. Структурированный ответ Gemini и локальные ссылки проверяются до передачи браузеру; SSE не раскрывает незавершённый JSON.

Фильтры предназначены для отклонения диагнозов, дозировок, обещаний результата и небезопасных медицинских рекомендаций. Они не гарантируют правильность каждого ответа. «Дента» — информационный помощник, не врач.

IP перед сохранением заменяется SHA-256-псевдонимом. По умолчанию он очищается через 24 часа, сообщения — через 30 дней. Это псевдонимизация, а не анонимизация.

Удаление выполняется при вызове защищённого маршрута `chat-retention`. Vercel вызывает его по расписанию; для другого хостинга нужен собственный планировщик. Отдельного фонового обработчика хранения чата нет.

## Заголовки браузера

Установлены `nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Permitted-Cross-Domain-Policies: none` и ограниченная `Permissions-Policy`. Для аутентифицированного API запрещено кеширование. HSTS и перенаправление на HTTPS включаются вне Development.

Content Security Policy пока не настроена. Её внедрение требует проверки внешних шрифтов, карт, CDN и других ресурсов; начинать следует с режима наблюдения.

## Служебные задачи

`/api/maintenance/*` скрыты из Swagger и требуют `Bearer <CRON_SECRET>`. При отсутствии секрета доступ отклоняется; сравнение выполняется за постоянное время.

Автоматическая отмена устаревших заявок выключена, пока не задано `BackgroundJobs:CleanupEnabled=true`. Флаги и ключи идемпотентности защищают создание напоминаний и последующих уведомлений от повторов.

## Автоматические проверки и остаточные риски

Dependabot отслеживает зависимости NuGet, Actions и Docker; CodeQL анализирует C# и JavaScript. CI собирает приложение и контейнер, проверяет обнаружение миграций, выполняет .NET- и JS-тесты. Отдельные процессы предусмотрены для Playwright, проверки опубликованного сайта и Gemini при наличии ключа.

| Ограничение | Что требуется при развитии |
|---|---|
| Нет MFA и восстановления пароля администратора | Проверенный процесс восстановления и MFA |
| Общий симметричный ключ JWT | Регламент ротации; оценка альтернатив при масштабировании |
| Локальный кеш отзыва сессий | Учёт задержки и отдельное проектирование глобального выхода |
| Нет SignalR backplane | Инфраструктура для нескольких экземпляров; восстановление состояния через REST |
| Нет CSP; клиент SignalR загружается с CDN | Проверенная политика, контроль целостности или локальное размещение |
| Изображения не декодируются и не сканируются | Дополнительная обработка при соответствующей модели угроз |
| Чувствительные данные в SQL | Шифрование, минимальные права, защищённые копии, сроки хранения |
| InMemory-тесты не доказывают поведение SQL | Интеграционные проверки блокировок, ограничений и миграций в SQL Server |
| Защита веток задаётся вне исходников | Настройка rulesets и обязательных проверок в GitHub |

Автоматизация не заменяет ревью, обновление зависимостей, проверку восстановления и независимый аудит.

Об уязвимостях сообщайте приватно по [SECURITY.md](../SECURITY.md). Не проверяйте атаки на реальных данных пациентов и не раскрывайте детали в публичных Issues.
