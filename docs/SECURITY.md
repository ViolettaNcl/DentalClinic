# 🔒 Безопасность

Этот документ описывает, какие меры защиты уже реализованы в проекте, и как устроено
управление секретами (паролями, ключами API).

## Управление секретами

Реальные значения (строка подключения к БД, ключ подписи JWT, ключи Gemini/ElevenLabs)
никогда не хранятся в репозитории. Вместо этого:

- в репозитории лежит [`appsettings.Example.json`](../appsettings.Example.json) —
  шаблон с тестовыми плейсхолдерами вместо реальных значений;
- сам `appsettings.json` с настоящими значениями создаётся локально каждым, кто
  разворачивает проект, и указан в `.gitignore` — в git не попадает;
- для локальной разработки значения удобно хранить через `dotnet user-secrets` (см.
  [`docs/DEVELOPER_GUIDE.md`](DEVELOPER_GUIDE.md), раздел 3);
- на проде — через переменные окружения хостинга (см.
  [`docs/DEPLOYMENT.md`](DEPLOYMENT.md), раздел 2).

## Реализованные меры защиты

| Мера | Где реализовано | Что даёт |
|---|---|---|
| Хэширование паролей (BCrypt) | `AuthController`, `Models/Patient.cs`, `Models/Admin.cs` | Пароли никогда не хранятся и не передаются в открытом виде |
| JWT с проверкой срока действия | `JwtTokenService`, `Program.cs` (`ClockSkew = TimeSpan.Zero`) | Токен нельзя использовать бессрочно или с «люфтом» по времени |
| Rate Limiting | `Program.cs`, политики `auth`, `appointment`, `chat`, `translate` | Защита от подбора пароля и накрутки затрат на платный AI API |
| CORS с белым списком доменов | `Program.cs`, `AllowedOrigins` в конфигурации | API не принимает запросы с произвольных сайтов |
| Глобальный обработчик исключений | `Program.cs` | Детали внутренних ошибок не «протекают» в ответ клиенту |
| Валидация входных данных | Data Annotations в `Models/*.cs` | Ограничения длины/формата (например, телефон, email) проверяются до записи в БД |

## Известные ограничения (честно, для понимания контекста)

- Rate limiting работает в памяти процесса — при развёртывании на нескольких инстансах
  потребуется общее хранилище (например, Redis).
- Нет ролей "второй администратор / супер-админ" — только плоское разделение пациент/админ.
- Загрузка аватаров хранится на диске сервера, а не в объектном хранилище — см.
  [`docs/DEPLOYMENT.md`](DEPLOYMENT.md) при масштабировании на несколько серверов.
